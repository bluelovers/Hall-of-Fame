# BUG-001: Data.php:418 foreach() Warning

> 修復日期：2026-05-10

---

## 問題描述

**檔案**: `HOF/Model/Data.php`
**函式**: `getLandAppear()`
**類型**: Warning / 潛在 Crash
**狀態**: ✅ 已修復

### 症狀

當 `getLandAppear()` 被呼叫時，PHP 拋出以下警告：

```
foreach() argument must be of type array|object, string given
```

發生在 `getLandAppear()` 的兩處 inner foreach 迴圈（行號 390 與 418）。

### 根因分析

```php
foreach ((array)$land['trigger']['item'] as $_data)  // 外層: (array) 轉型
{
    foreach ($_data as $_k => $_v)                    // 內層: 未檢查 $_data 是否為陣列
    {
        ...
    }
}
```

`(array)` 轉型對於非陣列值的行為是將其 wrap 為 `array(0 => value)`，因此當 `$land['trigger']['item']` 為純量值（如字串 `"item_id"`）時，外層 foreach 的 `$_data` 仍為該純量值（如 `"item_id"` 字串），導致內層 `foreach` 收到非陣列參數而拋出警告。

---

## 修復方式

在兩處 inner foreach 前加入 `is_array($_data)` 守衛條件：

### 修復 1: item trigger（原第 386-399 行）

```php
foreach ((array)$land['trigger']['item'] as $_data)
{
    $ok = -1;

    /**
     * 確保 $_data 為陣列才進行迭代
     * Ensure $_data is an array before iterating
     */
    if (is_array($_data))
    {
        foreach ($_data as $_k => $_v)
        {
            $ok = 1;

            if (!$user->item[$_k] || $user->item[$_k] < $_v)
            {
                $ok = 0;
                break;
            }
        }
    }
```

### 修復 2: time trigger（原第 414-427 行）

```php
foreach ((array)$land['trigger']['time'] as $_data)
{
    $ok = -1;

    /**
     * 確保 $_data 為陣列才進行迭代
     * Ensure $_data is an array before iterating
     */
    if (is_array($_data))
    {
        foreach ($_data as $_k => $_v)
        {
            $ok = 1;

            if (HOF_Helper_Global::gc_date($_k) != $_v)
            {
                $ok = 0;
                break;
            }
        }
    }
```

---

## 影響範圍

- 僅影響 `getLandAppear()` 函式
- 當 YAML 地圖資料（`Resource/Land/`）中的 `trigger.item` 或 `trigger.time` 欄位包含非陣列值時觸發
- 修復後，非陣列值被靜默跳過（`$ok` 保持 `-1`），不會影響現有功能
