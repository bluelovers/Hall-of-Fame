# BUG-003: AI Pattern 無法持久化 — 設定後重新載入頁面恢復為預設值

> 建立日期：2026-05-10
> 狀態：🔴 **調查中（根因範圍已縮小）**

---

## 問題描述

**檔案**: `HOF/Class/Char/Pattern.php`, `HOF/Controller/Char.php`
**類型**: 邏輯錯誤 / 資料持久化中斷
**狀態**: 🔴 未修復（根因範圍已縮小至 LOAD 流程）

### 症狀

1. 在 Action Pattern 頁面設定 Pattern（如 HP≤25% → FirstAid, HP≤50% → FirstAid）
2. 點擊「Set Pattern」或「Set & Test」
3. 頁面顯示「**パターン設定保存 完了**」— 表面上設定成功
4. 重新載入頁面（F5 / 導覽至其他頁面再返回）
5. Pattern 恢復為預設值（必ず→Attack, 必ず→Attack）

### 重現步驟

1. 以 demo/demo 登入
2. 選擇 Hero1 (Lv.2 Warrior)
3. 點擊 Action 進入 `/char/action?char=b3e304903f09e14b8386a49a1e1e01e3`
4. 設定 Pattern 1: 自分のHP が○○(%)以下 / 25 / FirstAid
5. 設定 Pattern 2: 自分のHP が○○(%)以下 / 50 / FirstAid
6. 點擊「Set Pattern」
7. ✅ 頁面顯示「パターン設定保存 完了」
8. 點擊瀏覽器重新載入
9. ❌ Pattern 恢復為「必ず→Attack」

## 調查過程

### Phase 1: 確認 YAML 持久化是否成功

**方法**: 設定 Pattern 後，立即讀取角色 YAML 檔案

**結果**: YAML 檔案 **正確寫入了 Pattern**

檔案位置: `hof/trust_path/dat/user/demo/char.b3e304903f09e14b8386a49a1e1e01e3.yml`

```yaml
# 設定前（預設值）
behavior:
  pattern: [{judge: "1000", quantity: "0", action: "1000"}, {judge: "1000", quantity: "0", action: "1000"}]
  # judge: 1000 = "必ず", action: 1000 = "Attack"

# 設定後
behavior:
  pattern: [{judge: "1101", quantity: "25", action: "3120"}, {judge: "1101", quantity: "50", action: "3120"}]
  # judge: 1101 = "自分のHP が○○(%)以下", action: 3120 = "FirstAid"
```

**結論**: `HOF_Class_Char_Type_Char::saveCharData()` → `HOF_Class_Yaml::save()` 流程正常運作。YAML 檔案確實被更新。

### Phase 2: 確認重新載入時 YAML 是否被覆寫

**方法**: 重新載入頁面後，再次讀取 YAML 檔案

**結果**: YAML 檔案 **仍然保留正確的 Pattern 資料**，未被覆寫

```yaml
behavior:
  pattern: [{judge: "1101", quantity: "25", action: "3120"}, {judge: "1101", quantity: "50", action: "3120"}]
```

**結論**: YAML 檔案資料是正確的。問題不在於資料被覆寫，而是 **載入/顯示邏輯** 沒有正確讀取 YAML 中的 pattern。

### Phase 3: 追蹤 LOAD 流程

**POST 儲存流程**（正常）:
```
_judge_pattern_change()
  → $this->char->pattern($pattern)    # Pattern::pattern() → 寫入 $this->char->behavior['pattern']
  → $this->char->saveCharData()       # 寫入 YAML 檔案
```

**GET 載入流程**（異常）:
```
_main_before()
  → $this->user->char($this->input->char)    # 從 YAML 載入角色資料
  → $this->char_detail()                      # 設定 $this->output->char ?
_main_action_action()
  → $this->output->pattern_max = $this->char->pattern_max()   # 顯示設定
```

**模板顯示** (`tpl/char/char.judge.php` line 13):
```php
$pattern = $this->output->char->pattern_item($i);
```

關鍵文件:
- `Pattern::pattern_item($idx)` (Pattern.php:248-250) — 直接回傳 `$this->char->behavior['pattern'][$idx]`
- `char_detail()` (Char.php:999) — 設定 `$this->output->char` 的方式是根因關鍵

---

## 根因分析

**推測根因**: `char_detail()` 方法中 `$this->output->char` 的設定方式導致模板讀取到錯誤的 pattern 資料。

YAML 檔案資料是正確的，因此問題一定在 GET 請求的載入鏈中：
1. `$this->user->char()` 載入角色後，`$this->char->behavior['pattern']` 是否正確？
2. `char_detail()` 是否覆蓋或重新設定 pattern？
3. `$this->output->char` 與 `$this->char` 是否是同一個物件？
